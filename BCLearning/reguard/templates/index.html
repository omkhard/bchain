▶ What is a Reentrancy Attack?

A reentrancy attack happens when an external call is made before internal state is updated. The called contract can recursively re-enter the vulnerable function.

// VULNERABLE
function withdraw(uint amount) public {
    require(balances[msg.sender] >= amount);
    (bool ok,) = msg.sender.call{value: amount}("");
    balances[msg.sender] -= amount; // Too late!
}
The 2016 DAO hack drained ~$60M ETH using this exact pattern.
▶ CEI Pattern (Checks-Effects-Interactions)

Always: 1) Check conditions → 2) Effect (update state) → 3) Interact (external call).

// SAFE — CEI
function withdraw(uint amount) external nonReentrant {
    require(balances[msg.sender] >= amount); // Check
    balances[msg.sender] -= amount;          // Effect first
    (bool ok,) = msg.sender.call{value: amount}(""); // Interact last
    require(ok);
}
▶ Why AST Analysis is Better Than Regex

Regex reads raw text — it can be fooled by comments, string literals, and multi-line expressions. A Solidity AST is the actual parsed structure.

// Regex would flag this as a CEI violation — it's not:
// "msg.sender.call{value: amount}" appears before "balances -="
// but the comment doesn't execute!

// AST knows the comment is not code and ignores it.
// (bool ok,) = msg.sender.call{value: amount}("");
Install solc to enable AST mode: pip install py-solc-x then python -c "from solcx import install_solc; install_solc('0.8.20')"
▶ Cross-Function Reentrancy

More subtle: attacker calls function A (which makes an external call), then re-enters via function B that shares the same state variable.

// VULNERABLE — cross-function
function withdraw() external {
    (bool ok,) = msg.sender.call{value: balances[msg.sender]}("");
    balances[msg.sender] = 0;
}
// Attacker re-enters via transfer() before balances[msg.sender] = 0
function transfer(address to, uint amt) external {
    require(balances[msg.sender] >= amt);
    balances[msg.sender] -= amt; // stale state!
    balances[to] += amt;
}
